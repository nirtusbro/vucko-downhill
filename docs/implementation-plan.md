# Vučko Downhill implementation plan

Goal: a complete one-thumb mobile skiing game following the supplied brief.

Architecture: a fixed-step simulation independent of Three.js; procedural low-poly scenery and articulated character; pointer/keyboard input; HTML menus and HUD; Web Audio effects. The skier moves through a fixed world, with camera and ski trails following actual position and heading.

Visual design: snow #f2f8ff, sky #85c9ed, navy #163d59, pine #245e59, racing red #e44343, ice #b6dcef. Rounded Trebuchet display type and system body type. Live mountain scene dominates all screen sizes; large thumb-level start action; minimal running HUD.

1. Skiing prototype: configure Vite/TypeScript; write failing physics tests; implement acceleration, steering inertia, resistance, gate crossing and recovery; render slope, skier, camera and several gates; validate touch and keyboard before visual expansion.
2. Visual identity: articulated wolf with face, ears, scarf, ski boots, poles and skis; instanced trees, mountain ridges, cabins, fences and rocks; pooled spray and curved world-space tracks. Inspect portrait and landscape renders.
3. Game loop: 20 handcrafted gates over a roughly 90-second course; combo scoring; start/tutorial/pause/finish/replay; persistent best score; reliable reset and pause-on-hidden behavior.
4. Polish and delivery: gesture-unlocked audio, mute, responsive safe-area UI, manifest and icons; build and test; browser exercise of steering, pause, replay, storage and completion; document local and phone access plus static deployment.

Validation: simulation tests at different frame rates; production TypeScript/build checks; browser interaction tests and screenshots at 390x844, 360x800, 430x932 and landscape. Real-device Safari/Chrome performance remains a physical-device check.

Birthday personalization: user requested a birthday gift for Ljubica. Add a home greeting, sparse pastel gift boxes and bunting outside the course, and 20 collectible table lamps centered between gates. Four shared procedural lamp models, +50 points per pickup, one-time collection, replay reset, gentle pickup animation and chime, HUD/finish collection counters. Keep the underlying skiing and gate combo unchanged.

Difficulty and faster birthday runs (22 September): add saved Easy/Classic/Expert selection, visible matching gate widths and separate best scores. Following the user's request for a faster game, raise cruising speeds to 24/30/36 m/s, start at half cruise speed and accelerate faster. Add a three-slot present pool: randomized safe landing positions, 1.8-second visible falls, gold ground rings, +200 one-time bonuses, collection animation/audio and HUD/results counts. Verify reachability in every mode, seeded random drops, landing/pickup/replay/finish behavior, production build and responsive browser layout. This supersedes the original slower course timing.

Closer gates and keepsake shelf: reduce successive gate spacing from 65 to 45 metres, finish 80 metres beyond the last gate, retaining halfway lamp detours. Add a home shelf with four illustrated lamp designs and cumulative counts. Persist each pickup immediately, including repeat designs and unfinished runs. Keep the shelf after replay and reload; retain session progress if storage is blocked. Verify full-course steering in all modes, storage validation and browser pickup-to-shelf flow, plus portrait and landscape layouts.

Two-thumb speed control: add a lower-left hold-to-boost button with independent pointer capture from steering, plus Space on desktop. Raise target speed by 45% while held, accelerate smoothly and ease back on release. Preserve steering and gate scoring; clear input on pause, replay, blur and finish; disable boost during tumbles. Show button feedback and a skiing tuck. Promote the selected difficulty's saved best to a visible home-screen high-score metric. Test both touch orders, independent release/cancellation, keyboard/reset and speed behavior in every mode.

Sparser pickups (22 September): the user reported lamps and presents appearing too often. Place 8 lamps per run instead of 20, chosen by the run seed with one lamp per band of two or three stretches so spots vary and never bunch, and hold each 5 metres wide of the line between gates so a pickup is a real detour. Drop the first present after 5.5 seconds and then every 9–14 seconds from a two-slot pool, giving three or four presents per run. The perfect on-slope score becomes 7,800. Verify seeded spread and spacing, drop gaps, reachability in all modes, and browser HUD counts and lamp placement.

Ghost from passed runs only (22 September): the user saw a ghost missing gates after passing a level cleanly. Two causes: a failed run with a higher score counted as the level best and so as the ghost, and ghosts recorded on earlier layouts of a level were still loaded. Count only passed runs as a level best, save the ghost with a fingerprint of the level layout, and drop any ghost whose fingerprint no longer matches.

Lamps without points (22 September): the user noted that lamps already owned lowered the maximum score on a replay. Make slope lamps worth no points and drop the rarity point table; goals are already shares of the gate score alone, so they stay as they are. Update the pickup feedback, results and README.

Beyond the summit (22 September): with the birthday game complete, the user asked for ten more very hard levels, 21 to 30, with no lamps and no presents, only hard obstacles. Extend the ladder to thirty with lamps confined to the first twenty, record cleared levels separately from finish lamps so bonus levels can be passed, switch presents off per level, fill every empty stretch of a bonus level with a rock, author ten designs with dense rock gates, weaves, line rocks, funnels, chicanes and hairpins at 44–49 m/s and goals of 90–97%, and list them in their own section of the level map with a mountain glyph in place of a lamp. Verify reachability with margin, the no-straight rule, no presents, and that older saves keep their clears.

Lamps kept only on a pass (22 September): the user asked that slope lamps join the collection only when the level is passed on that run. Move the save from the pickup to the finish, through a pure helper that lists the run's new pickups when it passed; show “pass to keep it” on pickup and, on a failed run, how many lamps were picked up but not kept. Update the how-to, collection and README texts, and test the helper for passed, failed, unfinished and replayed runs.

No boost (22 September): the user asked to remove boost entirely, and with it the boost-gated goals. Remove the hold-to-boost button, the Space and Enter bindings, the boost speed and turning factors, the skier's tuck and the boost test controller. Speed run and The summit become tight-par levels with goals at 94% and 97% of the gate maximum and a time bonus of 250 points per second against par at 1.1×. Update the how-to text, README and tests.

Clean passes and a reordered ladder (22 September): the user found Squeeze and Halfway sprint easier than the levels before them, and asked for them at 4 and 5 with the others shifted up, for the next level to be shown on the results screen above the table, for every gate to be required to pass, and for a points penalty on tumbles. Reorder the designs and retune their speeds and widths to the new positions, require zero missed gates plus the goal score to pass, deduct 300 points per tumble, show a next-level card with name, hint, lamp, gates and goal after a pass, and turn the HUD goal line red after a missed gate. Verify the sweep, the pass rule and the penalty.

Faster base speed (22 September): the user asked for a 15% faster base speed. Add a global speed scale of 1.15 applied to every authored level speed, derive par from the scaled speed, and retune the boost levels to a one-second demand with par 2% above cruising so a careful boosted run still clears them. Verify the full sweep again.

Harder ladder (22 September): the user found the game still easy and the first nine levels alike, and asked for more obstacles, more side-to-side movement and no gate pairs that can be skied straight unless an obstacle sits between. After agreeing a per-level brief for levels 1–9 (steer, forks, rhythm, holding a line, small inputs, reading ahead, approach angle, commitment, compression), re-author all twenty designs to a hard rule: consecutive gate openings never overlap sideways, or the stretch carries an on-line rock. Add line rocks for same-side pairs and stairs, narrow every level by about 0.5 m, add stray rocks throughout, and give the test controller path-based swerving so weaves and line rocks can be validated. Verify the rule, one feature per stretch, reachability with margin, boost gating and a failing straight line on every level.

Hand-placed levels and scenery (22 September): the user found the generated levels repetitive and easy, asked for interesting gate placements needing skill, more scenery, and for owned lamps not to reappear. Following the suggestion to author rather than generate, replace the generator with twenty explicit designs: every gate as [x, gap, width scale], plus per-level lists of lamp stretches, guard trees, stray rocks, rock gates and weaves, with no random numbers. Anchor rock features to the gate they lead into. Add fringe trees, snow bushes, glowing lamp posts along the fence and a chairlift. Hide lamps already in the collection on replay, exclude them from the count and score, and lower boost-level goals by their points. Verify one feature per stretch, hazards clear of gate lines, reachability with at least 0.4 m of margin, boost gating and the hidden-lamp rules.

Designed levels (22 September): the user asked for every element of a level to be fixed, for each level to introduce a challenge and get harder, for some late levels to require boost, and noted a level with five straight gates. Replace the parameter curve with a table of twenty named designs with hints, add a minimum swing and non-straight quick steps so no gates run straight, seed presents from the level, add per-level time-bonus rates, and derive the goal on boost levels from a perfect cruising run plus 1.5 seconds under par. Give the test controller a boost policy and verify boost levels fail without it and pass with it, that no level is passable straight, that presents repeat exactly, and that no more than two nearly straight stretches follow each other.

Twenty levels, five lamps each (22 September): the user found 100 levels too many and asked for 20, with the remaining lamps collectible inside the levels and tied to a level rather than random. Map level n to catalogue lamps 5n to 5n+4: four fixed slope pickups and the rarest as the finish lamp. Always place four pickups, filling from the longest stretches when few are comfortable, and let lamp-free rocks use any long enough stretch. Save pickups to the collection immediately; earn the finish lamp on a pass. Show the four slope lamps on the home card, group the level map by level with a Ski button, and report new lamps found on the results screen. Verify the lamp mapping covers all hundred once, reachability on all 20 levels across two seeds, immediate pickup saves and the browser flow.

Level ladder (22 September): the user preferred earning lamps to collecting them and asked for 100 unique, progressively harder levels, each awarding one lamp on completion, with a minimum score to pass. Replace the difficulty modes with a deterministic level generator: a tuning curve from level 1 to 100 for gate count, spacing, width, offsets, speed, pickups, hazards, quick follow-ups, same-side doubles and goal fraction, with per-gate and per-pickup lateral caps derived from the steering dynamics so every layout stays reachable. Level n earns catalogue lamp n; pickups become small copies of that lamp worth rarity points and never add to the collection. Add per-level progress storage (unlocked level, earned lamps, best scores), a level map replacing the gallery, home-screen level browsing, a goal readout in the HUD, a results reveal of the earned lamp with a next-level action, per-level ghosts and a par-based time bonus. Verify all 100 layouts distinct, monotone difficulty, every gate and pickup reachable with a passable goal, hazard rules, progress storage, and the browser flow of failing and passing a level.

Gameplay depth (22 September): the user found the game too easy and asked for all proposed changes. Seed rocks and trees into the course: a fork rock on the direct line at every lamp, a guard tree beside Rare and better lamps, and a rock in a difficulty-dependent share of lamp-free stretches. Tighten gates by 20% and raise cruising speed by 8% over the course. Widen the turning arc by 28% while boosting. Raise the combo cap to ×8 and add a +50 bullseye for crossing within a metre of the gate centre. Replace the strict alternation with a hand-placed layout including three quick 30–32 m follow-ups, two same-side doubles and 7 m swings in the last third, capped so every gate stays reachable after a lamp detour. Save the best-scoring run's path per mode and replay it as a translucent Vučko with a live ahead/behind readout. Tie rarity to risk with extra detour and 50–250 points. Add per-mode steering response and detour scale so Expert remains fair. Verify with multi-seed reachability in every mode, hazard placement rules, hazard-free present landings, ghost sampling and storage, and browser checks of hazards, the ghost, bullseye feedback and results.

Time scoring and the 100-lamp collection: add a finish-only bonus of 50 points per second under 90 seconds, clamped at zero, with a results breakdown. Catalogue 100 stable IDs across ten shapes/ten finishes and five rarities. Roll 20 distinct weighted designs per run, favoring undiscovered designs. Save actual picked-up catalogue IDs immediately and migrate the four legacy design counts. Replace the small shelf with a collection preview linking to a scrollable gallery; show uncollected lamps as black silhouettes and add status/rarity filters. Match slope models and gallery artwork, retain duplicate counts and show new discoveries at finish. Verify all designs obtainable, rarity weighting, save migration, single-award time scoring, browser pickup/gallery/reload and mobile layout.
